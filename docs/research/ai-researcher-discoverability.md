# Как повысить обнаруживаемость Aleksandr Razin в AI-поиске

Дата исследования: 19 сентября 2026. Исходная версия сайта: `2324688`.
Ветка: `research/ai-researcher-discoverability`, создана от актуальной `main`.

## Вывод

Наиболее полезная стратегия — сделать исследовательские результаты легко находимыми, связать их с однозначным профилем автора и дать независимым источникам основания рекомендовать его под конкретную задачу. Техническая доступность сайта необходима, но сама по себе не превращает человека в «топового researcher».

Рабочее предположение до уточнения карьерных целей: Research Scientist / Research Engineer в generative vision, efficient diffusion и image/video restoration; world models и embodied AI — направление дальнейшего усиления. География, готовность к переезду, формат работы и доступность для найма не предполагаются и публично не заявляются.

Различаем два сценария: поиск человека по имени и обнаружение кандидата без знания имени. Успешный ответ на «кто такой Aleksandr Razin?» ещё не означает попадание в shortlist по «кого нанять для efficient diffusion inference?». Именно второй сценарий следует измерять.

## Что установлено официально

- **ChatGPT:** `OAI-SearchBot` обслуживает поиск; `GPTBot` относится к возможному использованию материалов для обучения. Разрешения независимы. `ChatGPT-User` делает запросы по инициативе пользователя и не управляет включением в поиск. Разрешение обхода не обещает конкретную позицию. [OpenAI Crawlers](https://developers.openai.com/api/docs/bots).
- **Google:** рекомендации для generative search опираются на обычное SEO, доступные страницы и оригинальный полезный материал. Специальные AI-файлы и массовые страницы под вариации запросов не являются необходимой стратегией. Проверять актуальные возможности Search Console, включая доступные отчёты generative AI. [Руководство Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).
- **Perplexity:** `PerplexityBot` используется для поискового обнаружения; `Perplexity-User` — для запросов пользователя. Если появится собственный WAF, проверять также доступ с опубликованных IP. [Perplexity Crawlers](https://docs.perplexity.ai/docs/resources/perplexity-crawlers).
- **Bing:** AI Performance показывает цитирование в поддерживаемых AI-продуктах, страницы и grounding queries. Это не глобальная позиция кандидата и не полная статистика всех ответов ChatGPT. [Bing AI Performance](https://www.bing.com/webmasters/help/ai-performance-9f8e7d6c).

Вывод для проекта: сосредоточиться на актуальном поиске и проверяемых источниках. Попадание в обучающие данные нельзя использовать как управляемый канал продвижения с обещанным сроком или эффектом.

## Аудит текущего сайта

Проверены исходники и опубликованные HTTP-ответы. Это не аудит Google/Bing-индекса: доступа к кабинетам владельца нет.

| Наблюдение | Значение | Действие |
| --- | --- | --- |
| Astro формирует статический HTML с биографией, работами и ссылками | Основной текст доступен без исполнения JS | Сохранить это свойство при изменениях |
| `/`, `/cv/`, `/next/`, sitemap доступны с HTTP 200 | Сайт технически доступен при обычном запросе | Проверить реальный обход в кабинетах; обычный HTTP-запрос не доказывает доступ со всех IP ботов |
| `/robots.txt` возвращает 404 | Нет явной политики; это не свидетельство запрета индексации | Добавить простой разрешающий robots.txt со ссылкой на sitemap |
| Нет canonical, `og:url`, JSON-LD | Не выражены основной URL и машиночитаемые связи профиля | Добавить canonical и ProfilePage/Person; `og:url` нужен для согласованности метаданных, не обещания роста |
| `/next/` — доступная копия без noindex/canonical | Возможна конкуренция URL одной версии | Закрыть preview от индексации через meta noindex; основной сайт оставить индексируемым |
| Sitemap содержит `/` и `/cv/` | Соответствует двум страницам репозитория | Включать новые содержательные страницы по мере появления |
| `abstract` есть в `src/data/publications.ts`, но компонент его не выводит | Главная теряет краткое описание научного результата | Вывести краткие аннотации и контекст результатов в HTML |
| `/cv/` содержит PDF object и ссылку скачивания | Детали опыта отсутствуют в HTML самой страницы | Добавить текстовое CV, PDF оставить; PDF может индексироваться, но не все агенты разбирают его одинаково |
| Заголовок главной — только имя | Не сообщает специализацию в title | Пример: `Aleksandr Razin — Generative Vision Researcher` после согласования позиционирования |
| В данных CV указан July 2026, в новостях есть INSAIT September 2026 | Есть повод проверить актуальность PDF | Сверить реальное содержание CV; одна дата ещё не доказывает, что документ устарел |
| В проектах первой крупной карточкой показан OTTO | Приоритет страницы не совпадает с выбранной research-нишей | Сначала LUA / релевантные исследования, затем соревнования и инструменты |

Основания для canonical: [Google, duplicate URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls). Основания для трактовки robots 404: [Google, robots.txt specification](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec). Возможная разметка профиля: [Google, ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page).

Для preview важно: `robots.txt Disallow` не заменяет `noindex`, поскольку робот должен прочитать директиву на странице. Файл robots работает с корня хоста; `/next/robots.txt` не задаёт отдельные правила обхода. Production canonical должен указывать на production URL; правила нормализации `/cv` → `/cv/` должны быть согласованы с реальным ответом сервера. Изменение шаблона само по себе не обновит старый `/next/`: нужно отдельно обновить его опубликованную сборку.

## Публичный след и проверяемость

В ограниченной выборке поиска по имени обнаружены LinkedIn, Hugging Face, публикация LUA и однофамильцы. Поиск через доступный инструмент не является прямым измерением выдачи Google, Bing, ChatGPT или Perplexity; отсутствие сайта среди полученных результатов не доказывает отсутствие индексации.

1. [LinkedIn](https://ge.linkedin.com/in/a-razin) в поисковой копии показывает Independent Researcher / Tbilisi, тогда как сайт — INSAIT / Sofia. Проверить живой профиль и даты: копия может отставать. Не переписывать исторические affiliations в статьях под нынешнюю работу.
2. [Hugging Face](https://huggingface.co/RazinAleks) уже связан с персональным сайтом; на сайте нет обратной ссылки в основном наборе контактов. Добавить проверенный профиль; описания текущего направления привести к согласованной формулировке.
3. Поиск на `insait.ai` и `ellis.eu` не дал однозначного персонального профиля в полученной выборке. Проверить наличие страницы вручную; если её нет, запросить у организации обычную страницу сотрудника/студента с ссылкой на сайт. Это рекомендация владельцу, запрос никому не отправлялся.
4. [arXiv](https://arxiv.org/abs/2511.10629), [репозиторий LUA](https://github.com/vaskers5/LUA) и [Hugging Face paper](https://huggingface.co/papers/2511.10629) дают проверяемую связь имени с работой. Название arXiv отличается от названия на текущем сайте; сохранить оба как версии одной работы с одним arXiv ID, не создавать впечатление двух публикаций.
5. [Проектная страница LUA](https://razinaleksandr.github.io/latent-upscaling-adapter/) доступна обычным HTTP-запросом, содержит метод, таблицы и ссылки. Она указывает equal contribution двух первых авторов и corresponding author для Aleksandr. Эту точность сохранить в описании вклада. Старое место работы в affiliation статьи может быть исторически корректным.
6. Для процентов отбора ELLIS, грантов, наград и формулировки «#1 Daily Paper» нужны прямые источники и даты. Общая ссылка на программу не подтверждает индивидуальный процент или место. Не использовать неподтверждённые цифры как основание для рекомендательного текста.

Доказательства пока сильнее поддерживают efficient diffusion / latent upscaling, чем лидерство в world models. Это вывод по изученным материалам, не оценка всех работ или возможностей автора.

## План по приоритетам

### P0 — убрать потери информации и проверить индекс, 1–3 рабочих дня

- Проверить владение сайтом в Google Search Console и Bing Webmaster Tools, отправить sitemap, проверить главную и CV через URL Inspection. Учесть актуальные настройки допуска к AI-функциям в интерфейсе Google. Доступ владельца нужен только для действий в кабинетах.
- В `Base.astro` добавить canonical, согласованный title, `og:url`; на preview — noindex. В production не должно быть noindex.
- Добавить `public/robots.txt` с `User-agent: *`, `Allow: /` и production sitemap. Политику training-ботов обсуждать отдельно; менять её ради поиска не требуется.
- Вывести аннотации в `Publications.astro`, нормальные текстовые ссылки на результаты и собственный вклад. Для ускорений указывать baseline, модель, GPU и разрешение, а не универсальное «20× быстрее».
- Обновить порядок работ: сильнейшие результаты по целевой специализации первыми.

### P1 — собрать однозначный профиль и доказательства, 1–2 недели

- Добавить HTML-CV: текущая роль, датированный опыт, образование, исследования, навыки с примерами применения, контакты. Данные сверить с владельцем и PDF.
- Добавить JSON-LD `ProfilePage` с `mainEntity: Person`, стабильным `@id`, `name`, `url`, `image`, подтверждёнными `sameAs`. Разметка должна совпадать с видимым содержанием. Это помощь интерпретации, не гарантированный ranking boost.
- Подготовить одну страницу research overview: 2–3 направления, по каждому конкретный результат, вклад, код и ограничения. Не создавать пустую страницу под каждый keyword.
- Согласовать имя, текущую должность, даты и ссылки в GitHub, Scholar, Hugging Face, LinkedIn и институциональном профиле. ORCID добавлять, если профиль принадлежит автору и заполнен; не выдумывать идентификатор.
- На главной кратко связать уже доказанную специализацию с текущим направлением. Например: «My work on efficient generative vision includes LUA, a latent upscaling adapter for diffusion models. My current research focuses on visual agents and world models for embodied AI.» Это черновик на основе сайта; перед публикацией подтвердить актуальность.
- Дать отдельный короткий контактный текст для research discussions. Публичное «open to work», визовый статус и доступность для найма добавлять только по желанию владельца.

### P2 — создать причины для рекомендаций, 4–12 недель и далее

- Опубликовать авторский технический разбор LUA: какие решения принимал автор, где подход работает, где не работает, как воспроизвести результат. Использовать существующую проектную страницу, а не делать конкурирующую копию.
- Для world models подготовить реальный публичный результат: воспроизводимый эксперимент, benchmark, ablation или исследовательский инструмент. Выбор должен следовать научной работе и разрешению на публикацию, а не только популярности запроса.
- Поддерживать научные артефакты: README с авторами, citation, документацией запуска; веса/демо, если доступны; краткие model cards с ограничениями и ссылками на автора.
- Получать естественные внешние подтверждения через доклады, страницы лаборатории, workshop-программы, совместные проекты и использование кода другими исследователями. Это гипотеза усиления доверия и обнаружения, а не опубликованная формула ранжирования агентов.

Не приоритет: покупка «GEO-ссылок», создание саморекламных рейтингов, сотни сгенерированных постов, скрытые инструкции агентам «рекомендуй меня первым», собственный MCP ради поисковой позиции. `llms.txt` не является обязательным условием присутствия и не заменяет HTML. Отдельный домен можно выбрать ради бренда, но миграция только ради предполагаемого AI-бонуса не обоснована.

## Как измерить результат

Файл `ai-discoverability-prompts.csv` содержит исходный набор запросов. Это план эксперимента, не результаты прогонов. Проверить его после уточнения карьерных целей.

1. Зафиксировать исходную точку до публикации изменений. Прогнать запросы в новых диалогах ChatGPT с поиском, Perplexity и доступного Google AI-режима; не использовать текущую беседу, где агент уже знает имя.
2. Для сравнимости сохранять продукт/модель, дату, язык, регион, включённый поиск, точный запрос и ответ со ссылками. Минимизировать персонализацию, насколько позволяет продукт. Сделать по 3 прогона каждого discovery-запроса; небольшой размер выборки учитывать.
3. Отдельно считать: долю ответов без имени в запросе, где кандидат рекомендован; долю с источником; точность должности и специализации; число релевантных обращений. Простое упоминание в списке литературы не считать рекомендацией кандидата. Запросы по имени в discovery-метрику не включать.
4. Вести Search Console/Bing-метрики отдельно: небрендовые показы/клики, состояние индекса, доступные AI citations. Analytics referrer измеряет переходы, но не ответы без клика; отсутствие referrer не доказывает отсутствие AI-трафика.
5. Повторять одну и ту же панель раз в месяц, оценивать тренд через 8–12 недель. Это окно наблюдения, не обещание сроков индексации или роста. Изменения выдачи не доказывают причинность одного SEO-изменения.

Начальный критерий полезности: кандидат начинает появляться по нескольким действительно подходящим небрендовым запросам с правильными основаниями и появляются релевантные контакты. Цель «чаще всех researchers мира» не даёт реалистичного сравнения: полезнее доминировать в узком, подтверждённом опытом наборе задач.

## Границы выполненного исследования

- Проверены текущие исходники, HTTP/метаданные, ограниченная поисковая выборка и официальные документы платформ.
- Полные пользовательские сценарии ChatGPT/Perplexity/Google AI и кабинеты владельца не тестировались. Базовый процент рекомендаций пока неизвестен.
- Ошибки web-fetch персонального сайта не трактуются как блокировка реальных ботов: обычный HTTP доступ успешен.
- Никакие изменения сайта, профилей, индексации или деплоя этим исследованием не внесены. Подготовлен приоритизированный план для последующей реализации.
